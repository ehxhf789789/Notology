## 2. Architectural choices

### Floating-UI as the only positioning dependency

`@floating-ui/react@0.27.19` is the single dep added in this commit
(~30 KB gzipped; Q6 default-accepted). Every primitive that needs
viewport-aware positioning, focus trap, portal mount, list navigation,
or typeahead routes through Floating-UI hooks. No second positioning
library. No hand-rolled `getBoundingClientRect` math.

### `cloneElement(trigger, ...)` pattern

`Tooltip`, `Popover`, and `DropdownMenu` accept a single React element
as `trigger` and inject `ref` + ARIA + event handlers via `cloneElement`.
This lets callers write:

```tsx
<Tooltip content="Save (Ctrl+S)"><Button icon={<Save />} /></Tooltip>
```

without a wrapper element that would break flex/grid layout. `useMergeRefs`
preserves any existing ref the child had.

### Toast module-level queue

`toast({ ... })` works from anywhere, not just inside React. This matches
how the existing `features/shared/Toast.tsx` is called from Tauri event
listeners and async error paths. `<Toaster />` mounts once at app root,
subscribes to the queue, and re-renders on every change.

### Dialog focus management

`FloatingFocusManager` (Floating-UI) handles focus trap + return-focus
without needing `focus-trap-react`. `FloatingOverlay lockScroll` prevents
background scroll. `useDismiss` with `outsidePress + escapeKey` props
makes ESC / backdrop click configurable per dialog.

### Tabs / SegmentedControl: no Floating-UI

These don't position floating panels — they're pure radio-group + state.
Kept dep-free for the lightest possible bundle slice.

## 6. Notable trade-offs / decisions

| Decision | Reasoning |
|---|---|
| **No sub-menu support in DropdownMenu yet** | Plan §3 doesn't require it. Adds significant complexity. Land in 5.0.7 or 5.0.8 if needed by a real surface. |
| **ContextMenu uses imperative API (not right-click hook)** | Caller already has context-menu detection logic ([`features/context-menu/`](../../../src/features/context-menu/)). Primitive accepts `position` from event so existing logic ports cleanly without behavior change. |
| **Toast uses module-level queue** | Matches existing app pattern where async backends emit toasts. `useToast()` hook delegates to the same module-level functions for ergonomics. |
| **Dialog renders no header when no `title` + `hideCloseButton`** | Common for confirmation dialogs that just need a body. Caller passes `ariaLabel` for screen readers. |
| **Select option labels can be `ReactNode`** | Allows icon + label compositions. Typeahead matching uses optional `searchText` string for accessibility. |
| **`<Tabs>` panels unmount by default** | Saves work on heavy panels (Search results, Graph). `keepMounted` opt-in per panel for surfaces that need stable state across tab switches. |
