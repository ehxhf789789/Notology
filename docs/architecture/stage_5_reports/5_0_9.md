## D. Component API summary

### `<HoverWindowChrome>`
```tsx
interface HoverWindowChromeProps {
  window: HoverEditorWindowProps['window'];      // from hoverAnimationUtils
  title: string;
  externalAction?: { onClick, icon: ReactNode, label: string };  // optional
  children: ReactNode;                            // viewer body
  className?: string;                             // chrome root extra class
  bodyClassName?: string;                         // body div extra class
  logLabel?: string;                              // DEV log prefix
}
```

### `<ViewerToolbar>` + helpers
```tsx
<ViewerToolbar position="top">
  <ToolbarZoom value={zoom} onZoom={setZoom} zoomOutLabel={t(...)} zoomInLabel={t(...)} />
  <ToolbarPageNav page={p} total={n} onChange={setPage} prevLabel={t(...)} nextLabel={t(...)} />
  <ToolbarSheetTabs sheets={names} active={i} onSelect={setSheet} />
</ViewerToolbar>
```

## E. Deferred — carries to 5.0.9-followup

| Item | Why | Carries to |
|---|---|---|
| **DOCX/HWPX/PPTX/XLSX adopt `<ViewerToolbar>`** | Each office viewer (300–520 lines) wires its own zoom hook (`useViewerZoom`) + page state + sheet selection. Mechanical replacement of `.docx-toolbar` JSX with `<ViewerToolbar>` is straightforward but the helpers need to be wired to existing local state — significant per-viewer testing for behavior preservation. Deserves its own sub-stage so a regression in any single office format can be bisected cleanly. Toolbar primitive is in place; office viewer migration is a stack of 4 narrow edits. | 5.0.9e-followup |
| **PptxViewer / XlsxViewer ToolbarSheetTabs wire** | XLSX has live sheet tabs that drive grid re-render; needs careful state lift from current `.xlsx-toolbar` JSX to the helper. | Part of above |
| **HoverDocumentViewer adoption** | A wrapper file (`HoverDocumentViewer.tsx`) exists that dispatches to DOCX/HWPX/PPTX/XLSX — its chrome may also be a Hoover candidate or already absorb HoverWindowChrome via the underlying viewer. Quick audit needed before deciding. | 5.0.9-followup |
| **HoverWebViewer `<HoverDocumentViewer>` cross-reference** | The host wrapper (`HoverEditor.tsx` / `HoverWindowApp.tsx`) routes file extensions to a viewer; verify none of the 4 migrated viewers receive a chrome from BOTH the wrapper AND the primitive. | 5.0.9 verification pass |
