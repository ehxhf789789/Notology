## B. What landed (5.0.10a)

### B.1 MEMO_COLORS hex array → Tier-3 tokens
- Promoted CalendarHomeView's hardcoded `['#FF6B6B', '#FF922B', '#FCC419', '#51CF66', '#339AF0', '#7950F2', '#F06595']` to themes.css as `--c-memo-stripe-{1..7}` (7 new Tier-3 tokens).
- Mobile + desktop calendar share the token names so a future palette tweak ripples across both.
- CalendarHomeView now references `MEMO_COLOR_VARS = ['var(--c-memo-stripe-1)', ...]` constants.

### B.2 NOTE_TYPE_COLORS hex map → existing note-type-colors.css tokens
- NoteListView's `NOTE_TYPE_COLORS` (10 hardcoded hex) → existing `--{type}-color` CSS vars from `src/styles/base/note-type-colors.css` (defined for light + dark already).
- Renamed local map to `NOTE_TYPE_COLOR_VARS`; `getTypeColor` returns CSS-var strings.
- Single source of truth across mobile note list, desktop search rows, desktop graph nodes.

### B.3 i18n migration — relative time + calendar + UI
- `formatDate(mtime, language)` reused across NoteListView + SearchView. Korean "방금 / N분 전 / N시간 전 / N일 전" → 4 new i18n keys `mRelJustNow / mRelMinAgo / mRelHrAgo / mRelDayAgo` (ko + en).
- CalendarHomeView weekday + month labels reuse desktop 5.0.7d keys (`calWeekday{0..6}`, `calMonth{0..11}`) — same source of truth as desktop Calendar.
- Long-form Korean weekday (월요일) computed at runtime: ko = `${short}요일`, en = native `Intl.DateTimeFormat('en-US', {weekday: 'long'})`.
- 9 new mobile-calendar i18n keys (`mCalPrevMonth / NextMonth / Today / Empty / EmptyHint / YearMonth / DateLabel / DateLabelToday / Count`).
- SearchView's `#339AF0` inline hex (recent-note dot) → `.m-search-recent-note-dot { background: var(--c-blue) }` in mobile.css.
