## C. PathDisplay primitive

**API (locked for this stage):**
```ts
interface PathDisplayProps extends HTMLAttributes<HTMLDivElement> {
  path: string;
  onReveal?: (path: string) => void;
  revealLabel?: string;
}
```

**CSS class:** `.ds-path-display` (monospace block, gap, IconButton reveal slot).

**Live consumers (1):** `FaststartMigrationModal` done view (backup_dir).

**Identified future consumers (deferred):**
- TrashPanel per-entry `.trash-panel-entry__path` — could replace with PathDisplay + reveal-restore action, but the entry has additional metadata + system-badge so a row wrapper is needed. Followup.
- NasFolderBrowser pick mode `<code className="nas-browser-pick-path">` — purely visual now (no reveal action available remotely). Could swap if a reveal-in-NAS-browser action lands.
- MigrationModal — does not display a backup path block today (sync-v1 stores in `.notology/sync-v1-backup` but the modal doesn't surface it). Add if HanBin wants symmetry with FaststartMigrationModal.

When 3+ concrete consumers materialize, revisit API to add `truncate` strategy + `copy` action.
