## B. What landed in this sub-stage

### B.1 Universal `prefers-reduced-motion` guard
- Added to `src/styles/layout/animations.css` end-of-file:
  ```css
  @media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
      animation-duration: 0.01ms !important;
      animation-iteration-count: 1 !important;
      transition-duration: 0.01ms !important;
      scroll-behavior: auto !important;
    }
  }
  ```
- The universal `*` selector + `!important` ensures every animation, transition, and scroll behavior across the entire stylesheet cascade is overridden when the user has the OS-level "reduce motion" preference. Animation NAMES stay observable in devtools (so author intent is still visible) — only durations collapse.
- This single rule supersedes the absent per-file guards in: `animations.css` (sidebarOpen/Close, fadeIn/Out, modalOverlayEnter), `loading-screen.css` (fadeIn, slideUp, spin), `sketch-editor.css` (sketch-node-enter, pulseTarget, handleFadeIn, sketch-sync-spin), `hover-editor.css` (hover-window-flash, hoverItemSlideIn, skeleton-shimmer), `sync.css` (sync-spin, conflict-pulse, vault-popover-in, nas-fade-in), `migration.css` (progress-bar transition), `calendar.css` (nav-button transitions).

## E. Verification

- Visual: with `Settings → Accessibility → Reduce Motion` enabled on macOS / Windows, opening a hover window should snap rather than animate; sidebar collapse is instant; loading spinner doesn't spin (but the spinner element itself still renders, just frozen).
- Authoritative: `prefers-reduced-motion: reduce` is the canonical CSS media query — no JS shim required, supported in all current Tauri WebView2 / WKWebView builds.
- No regression risk for users WITHOUT the preference: the guard is gated behind the `@media` rule and ignored entirely otherwise.
