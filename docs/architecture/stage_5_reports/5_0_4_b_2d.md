## v2 변경 요약 (v1 smoke test 실패 후)

v1 에서 wrapper-level `addEventListener` 가 작동 안 함 (HanBin 보고: 우클릭 메뉴 안 뜸, edge-zone 커서 배치 안 됨). 추정 원인:

1. **WikiLink 의 contextmenu plugin 이 먼저 가로챔** — `editorPool.ts` 에서 WikiLink 가 MediaEmbed 보다 먼저 등록됨. WikiLink 의 `handleDOMEvents.contextmenu` 가 비-위키링크 클릭을 `onEditorContextMenu` 로 보냄 → preventDefault 호출됨 → 내 wrapper-level listener 가 (이론상 먼저 fire 해야 하지만) WebView2 의 이벤트 순서 quirk 로 인해 작동 안 함
2. **시각적 깨짐** — wrapper padding 10px 0 + outline-offset -7px 조합이 가로축에서 outline 을 content 안쪽으로 끌어당겨 "ring 이 더 좁아 보임"

### v2 수정

1. **WikiLink contextmenu handler 수정** — target.closest('.wiki-image-embed-wrapper, .math-node, .link-card') 인 경우 early return false → 다음 plugin 에게 양보
2. **MediaEmbed 의 contextmenu + mousedown(edge-zone) 을 view-level plugin 으로 이전** — `addProseMirrorPlugins` 에 새 Plugin 등록 (검증된 패턴: WikiLink 와 동일)
3. **Math 의 contextmenu 를 MathTrigger plugin 으로 이전** — 같은 패턴
4. **LinkCard 의 React onContextMenu 유지** — WikiLink 가 `.link-card` 를 skip 하므로 React-root 레벨의 handler 가 발화됨
5. **DOM 재구성** — wrapper 안에 새 `.wiki-image-embed-inner` 추가. wrapper 는 hit-test 용 padding 만, inner 는 시각적 outline/hover/selected ring 담당. ring 이 visible content 만 정확히 trace함
6. **mousedown 에 `event.button !== 0` 가드** — 우클릭의 mousedown 이 edge-zone 처리되는 부작용 차단

## 1. 무엇이 바뀌었나 (한 줄 요약)

오디오/이미지/링크카드의 우상단 `×` 버튼이 사라졌습니다. 모든 atom (수식 포함) 삭제는 **마우스 우클릭 → "X 삭제"** 로 통일됐습니다. 동시에 임베드 위/아래의 빈 공간(상하 10px)을 클릭하면 그 위치에 커서가 들어가도록 명시적 처리를 넣었습니다 — "임베드 사이에 텍스트 넣기"가 비로소 동작합니다.

## 4. 자체 검증 (이미 통과)

| 검증 | 결과 |
|---|---|
| `npx tsc --noEmit` | ✅ 클린 |

`test:atom-edge` 의 16 케이스가 검증하는 시나리오:
- 가장자리 (top 0px, top 5px, edge boundary 10px)
- 중간 영역 (50px 위치 → middle)
- 반대쪽 가장자리 (bottom boundary, bottom 5px from end)
- 경계 밖 (음수 Y, height 초과)
- 0-height degenerate
- 10px 미만의 작은 wrapper (자동 edge 축소)
- 1px wrapper (effectiveEdge=0 short-circuit)
- 음수 edgePx
- 두 임베드 stacked 시나리오 (각 wrapper 의 padding 영역 클릭 → before/after 정확히 매칭)

## 5. 사람 평가가 필요한 부분 (smoke test 스크립트)

자동 검증으로 잡을 수 없는 시각/대화형 부분입니다. 각 항목에 통과/실패 표시 부탁드립니다.

### 5.1 시각 — `×` 버튼이 사라졌는가

1. ▢ 새 노트 만들고 오디오 파일을 드래그해 첨부 → 카드에 우상단 `×` **없어야 함**
2. ▢ 같은 노트에 이미지 첨부 → 이미지 카드에 우상단 `×` **없어야 함**
3. ▢ 같은 노트에 동영상 첨부 → 동영상 프레임에 우상단 `×` **없어야 함**
4. ▢ URL 을 붙여넣어 LinkCard 가 뜨면 → 카드에 우상단 `×` **없어야 함**

### 5.2 기능 — 우클릭 삭제

5. ▢ 오디오 카드 어디든 우클릭 → **"임베드 삭제"** 메뉴 한 줄 표시 → 클릭하면 카드 사라짐
6. ▢ 이미지 카드 우클릭 → 동일하게 "임베드 삭제" → 삭제
7. ▢ 동영상 카드 우클릭 → 동일
8. ▢ LinkCard 우클릭 → **"링크 카드 삭제"** → 삭제
9. ▢ 인라인 수식 `$x^2$` 우클릭 → **"인라인 수식 삭제"** → 삭제
10. ▢ 블록 수식 `$$y=mx+b$$` 우클릭 → **"블록 수식 삭제"** → 삭제
11. ▢ 위키링크 chip `[[note]]` 우클릭 → 기존 메뉴 (열기 / 이름변경 / 삭제 등) 그대로 표시 — **변경 없어야 함**

### 5.3 기능 — atom 사이 커서 배치 (이번 변경의 핵심)

12. ▢ 오디오 임베드 2개를 연달아 첨부 → 두 카드 사이의 빈 공간 (10–20px) 클릭 → **커서가 그 자리에 떠야 함**
13. ▢ 커서가 뜬 상태에서 "사이텍스트" 입력 → 두 임베드 사이에 글자가 들어가야 함
14. ▢ 오디오 카드 바로 위 5px 정도 위치 클릭 → 커서가 임베드 직전에 배치 → Enter 누르면 임베드 위로 빈 줄 생성
15. ▢ 오디오 카드 바로 아래 5px 정도 위치 클릭 → 커서가 임베드 직후에 배치 → 타이핑하면 임베드 뒤로 글자 입력
16. ▢ 카드 중앙 (재생/볼륨 버튼 영역) 클릭 → **NodeSelection 파란 테두리** (기존 동작 유지) — 텍스트 커서 배치되지 **않아야 함**
17. ▢ 재생 ▶ 버튼 클릭 → 정상 재생 (커서 배치되면 안 됨)
18. ▢ 시크바 드래그 → 정상 시크 동작

### 5.4 회귀 검사

19. ▢ 위키링크 chip 단일 클릭 → 이전과 동일하게 chip selection 표시
20. ▢ 위키링크 chip drag → drag-reorder 동작 유지
21. ▢ 수식 더블클릭 → 편집 popup 정상 표시 (한글 IME 입력 안전)
22. ▢ 단일 atom 만 있는 노트에서 Backspace / Delete 키 동작 (선택된 노드 삭제) — 기존 동작 그대로

## 6. 알려진 한계 & 후속 작업

- **CSS orphan**: `.wiki-image-embed-delete` 클래스 정의 + `link-card-delete` 클래스 정의가 CSS에 남아있음. DOM에서 더 이상 렌더되지 않으므로 무해. 다음 atom-CSS 정리 commit (5.0.4b 마무리 시점) 에서 일괄 삭제 예정. 다른-트랙 작업이 같은 파일에 진행 중이라 surgical commit 유지를 위해 현 단계에선 손대지 않음.
- **i18n orphan**: `deleteImageEmbed` 키가 i18n.ts 에 정의되어 있지만 더 이상 사용 안 함. 같은 정리 commit에서 제거.
- **MediaEmbed 만 edge-zone 적용**: Math 와 LinkCard 의 edge-zone 은 별도 wrapper padding 구조 작업이 필요해 일단 contextmenu 만 통일. HanBin이 12-15 시나리오가 OK 라면 같은 패턴을 다음 turn에 Math/LinkCard에도 확장.
- **WikiLink chip selection ring**: 다른 atom들과 outline 스타일 살짝 다름. 통일은 시각 디테일 영역이라 5.0.4b-3 (bubble menu + toolbar) commit 합류 시 처리.
