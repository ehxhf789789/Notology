**Status**: ✅ Acceptance criteria met — ready for HanBin visual sign-off

## 1. Purpose

Replace ad-hoc CSS variables with a strict **three-tier token system** so every
sub-stage that follows (5.0.2 component library through 5.0.10 mobile rewrite)
has a single source of truth for color, spacing, type, radius, motion, and
shadow.

Before 5.0.1, three independent token sets coexisted:

| Source | Naming | Theme handling |
|---|---|---|
| `src/design-system/tokens.css` | iOS-flavored (`--c-blue`, `--tx-1`, `--sp-1`, `--fs-17`) | Light + `[data-theme="dark"]` in same file |
| `src/styles/tokens.css` | Generic (`--space-N`, `--radius-N`, `--z-*`, `--font-N`, `--shadow-N`) | Mode-agnostic only |
| `src/styles/base/themes.css` | Themes v1 (`--bg-primary`, `--text-primary`, `--accent-primary`) | Three explicit selectors (light / dark / system) |
| `src/styles/theme.ts` (JS) | `--color-bg-*`, `--typo-*` (runtime-injected) | Built per-mode at boot |

Stage 5.0.1 keeps every legacy name as a backward-compat alias so all 74 CSS
files keep rendering identically, while introducing the canonical Tier 2
semantic API every new sub-stage will consume.

## 2. Token taxonomy landed

### Tier 1 — Primitives (`src/design-system/tokens.css`)

Raw values, **never** referenced by component CSS. Audited by
`audit-tokens.mjs` — only `tokens.css`, `mobile-tokens.css`, and
`themes.css` may use them.

| Family | Count | Range |
|---|---|---|
| `--primitive-gray-*` | 12 | 0 → 1000 |
| `--primitive-blue-*` | 10 | 50 → 900 |
| `--primitive-red-*` | 10 | 50 → 900 |
| `--primitive-amber-*` | 10 | 50 → 900 |
| `--primitive-green-*` | 10 | 50 → 900 |
| `--primitive-purple-*` | 10 | 50 → 900 |
| `--primitive-space-*` | 13 | 0 → 96px (4px grid) |
| `--primitive-radius-*` | 9 | 0 → 9999px |
| `--primitive-fs-*` | 8 | 10 → 32 |
| `--primitive-fw-*` | 4 | 400 → 700 |
| `--primitive-lh-*` | 3 | 1.2 / 1.5 / 1.7 |
| `--primitive-shadow-*` | 3 | depth 1 / 2 / 3 |
| `--primitive-font-*` | 3 | sans / mono / display |

### Tier 2 — Semantic (`src/styles/base/themes.css`, light + dark)

Components consume these names. Every Tier 2 token resolves to a Tier 1
primitive or to another Tier 2 token. Light and dark variants live side-
by-side in `themes.css` — no more `*-dark.css` parallel theme files for
Tier-2 semantics.

New canonical Tier 2 names introduced in this sub-stage:

- **Surface**: `--bg-app`, `--bg-elev-1/2/3`, `--bg-input`, `--bg-input-hover`, `--bg-input-active`
- **Text**: `--tx-1/2/3`, `--tx-disabled`, `--tx-on-accent` (legacy `--tx-4` kept as alias)
- **Border**: `--bdr-1/2/3`, `--bdr-focus`
- **Accent**: `--c-accent`, `--c-accent-hover`, `--c-accent-pressed`
- **Status**: `--c-success/warning/danger/info` + paired `--c-on-*`
- **Shadow**: `--shadow-pop`, `--shadow-modal`, `--shadow-overlay`, `--shadow-inset`
- **Motion**: `--motion-fast/normal/slow`, `--ease-standard/accelerate/decelerate`
- **Type scale (semantic)**: `--fs-caption/body/title/h3/h2/h1`
- **Spacing (semantic)**: `--space-xs/sm/md/lg/xl/2xl/3xl`
- **Line-height**: `--lh-tight/normal/relaxed`

### Tier 3 — Component (`src/design-system/tokens.css`)

Opt-in component knobs. Currently:

`--titlebar-height` (36), `--toolbar-height` (44), `--statusbar-height`
(26), `--modal-radius`, `--btn-primary-{bg,fg,bg-hover,bg-active}`,
`--modal-backdrop-bg`.

### Reduced-motion override

`@media (prefers-reduced-motion: reduce)` collapses every motion duration
(both new `--motion-*` and legacy `--dur-*` / `--duration-*`) to 1ms.
First piece of Stage 5.0.12 a11y work landed early because the token file
was the natural home.

## 3. Themes.css consolidation

Single file with three explicit selectors:

1. `:root` — default light values (also drives an OS-light system theme via
   absence of `data-theme`)
2. `html[data-theme="light"]` — explicit light
3. `html[data-theme="dark"]` — dark
4. `@media (prefers-color-scheme: dark)` for `html[data-theme="system"]`
   and bare `:root`

All legacy variables preserved 1:1:

- iOS palette (`--c-blue` … `--c-pink`, `--c-gray`)
- Themes v1 (`--bg-primary`, `--text-primary`, `--accent-primary`, `--border-color`, `--shadow-color`, `--bg-input`, etc.)
- Calendar colors (`--calendar-today-bg`, `--calendar-selected-bg`, `--calendar-selected-border`)
- Code highlight palette (`--code-bg`, `--code-keyword`, `--code-string`, …)
- Cell + sketch-node palettes (`--cell-blue`, `--node-purple`, …)
- Shadow scales from both legacy sources (`--shadow-sm/md/lg/xl/xs/focus` + `--sh-sm/md/lg/hw`)

`document-viewers-dark.css` is **intentionally retained** until the Stage
5.0.9 viewer redesign — that sub-stage will fold its rules into the
unified theme.

## 5. Backward-compat decisions (noted divergences from plan §2)

| Token | Plan target | Landed | Reason |
|---|---|---|---|
| `--radius-lg` | 10px | 8px | Existing surfaces (cards, buttons, list rows) depend on 8px — bumping would visually shift every Stage-4.x screen. New 10px name lives at `--radius-pop`. |
| `--radius-xl` | 16px | 12px | Same reason. 16px lives at `--radius-2xl` (legacy) and `--primitive-radius-16`. |
| `--radius-full` | 9999px | 50% | Used historically for circular avatars/icons. The 9999px "pill" intent now lives at `--radius-pill`. |
| `--ease-out`, `--ease-in-out`, `--spring` | replaced | preserved | Active in motion-heavy surfaces (sketch editor, hover windows). New `--ease-standard/accelerate/decelerate` names added in parallel. |

These deltas are documented inline in `tokens.css` and re-asserted here so
later sub-stages can revisit them per surface (the audit script will not
flag them — only Tier-1 leakage is blocking).

## 6. Mobile-tokens.css sync — **DEFERRED**

`src/design-system/mobile-tokens.css` is currently **untracked** in git
(never committed — it lives in the 180-file mobile-track in-flight work
described in `project_working_tree_state.md`). Per the "don't sweep other-
track files into 5.0.1 commits" policy, this sub-stage does **not** touch
it.

The Tier 2 design is intentionally compatible: every mobile-specific token
in that file has the same name as the existing token, and the new `--bg-*`
/ `--tx-*` / `--c-*` semantic tokens from `themes.css` inherit
automatically into mobile. When the mobile track lands or when 5.0.10
begins, that sub-stage will sync mobile-tokens.css to consume Tier 1
primitives directly (a ~30-line refactor; the new shape is sketched out
in this session's git history if needed).

The audit script's source-file whitelist already includes
`src/design-system/mobile-tokens.css` so a future sync commit will not
trip Tier-1 leakage detection.
