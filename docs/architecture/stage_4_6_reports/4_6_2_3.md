### UX flow (open-vault → modal)

```
openVault(selected)
  → libraryCommands.checkMigrationNeeded(selected)        // Stage-4 migration
```

Both modals can theoretically queue if both apply; in practice a Stage-4 vault that just migrated has refs that 4.6 then probes. The UX is sequential: user dismisses Stage-4 modal first, then sees the faststart prompt.

### Findings from the dry-run

#### F-1 (informational, **expected**) — 1 already-faststart skip works

`JSON-이해하기.mp4` (14.40 MB) returns `is_faststart=yes`. This was added more
recently — likely already faststart on the source. Production `run()` will
log it as `SkippedAlreadyFaststart` and not re-mux. ✓

#### F-2 (informational, **finding**) — cross-note dedup duplicates surface as 2 ref-level entries

`06주차-Part-01.mp4` and `06주차-Part-02.mp4` each show **twice** in the
enumeration with identical sha256. This is HanBin's vault: the same physical
attachment is linked from two notes via cross-note dedup (`linked_notes`
contains 2 note_ids, only 1 ref + 1 blob). `FaststartMigration::run()`
currently iterates ref-level (`store.all_refs().filter(is_video)`), so it
would issue 2 `apply_faststart` calls for the same blob, then 2
`swap_ref_sha` calls (both producing the same new sha because the algorithm
is deterministic — Stage 4.5.1 verified).

**Production effect**: correct (both refs end up pointing at the same new
faststart sha) but **wasteful** — `apply_faststart` runs twice per shared
blob, doubling the work for the affected files. For HanBin's vault that
means 2 extra re-muxes (~500 MB and ~1.1 GB extra read/write), adding
~30 s of work at 50 MB/s.

**Fix**: dedupe candidates by sha256 before running. Track as
`stage-4.6.3-followup-dedup-candidates-by-sha`. Non-blocker (correctness
preserved); should land as a small follow-up patch.

#### F-3 (informational) — backend `check_needed` matches the in-app prompt exactly

The same `FaststartMigration::check_needed()` returns identical numbers
whether called from this standalone dry-run or from the in-app
`faststart_migration_check` Tauri command. The frontend modal will display
"9개의 영상 파일이… 8.39 GB" — matching the dry-run report verbatim.
