Per-entry status: `Converted` / `SkippedAlreadyFaststart` / `Failed`. The
journal at `.notology/attachments/faststart_journal.json` records per-id
old_sha → new_sha + status + timestamp.

Backup: ref JSONs copied to `.notology/attachments.pre-faststart-migration/refs/`
before any swap. Blobs **not** copied (the original moov-at-end blob stays
in CAS until `sweep_orphans()` runs, so ref-level rollback restores the
pointers).

### AttachmentStore helper
`swap_ref_sha(id, new_sha, new_size)` — atomically updates a ref's
`sha256` + optional `size_bytes`, resets `sync_etag` + `remote_path`
(forces re-push on next sync), persists ref JSON. Does NOT delete the old
blob (caller manages GC after verification).

- `faststart_migration_decline(vault_path)` → persists decline marker

## Algorithm (from STAGE_4_6 plan §Algorithm)

For each video-tier ref (`tier == Video || mime_type starts "video/" ||
extension in {mp4, mov, m4v}`):
1. `is_faststart(blob_path)` probe.
2. If true → `SkippedAlreadyFaststart`.
3. Else → `apply_faststart(blob, tmp)` (Stage 4.5.1 determinism-verified).
4. Read tmp → compute new sha256 → write to CAS path of new sha (rename
   first, copy fallback).
5. `swap_ref_sha(id, new_sha, new_size)` updates ref atomically.
6. Old blob left in place — caller invokes `sweep_orphans()` after the
   migration completes successfully to GC it.

Per-entry independence: a single failing entry doesn't abort the run;
the journal records `Failed` and the loop proceeds to the next entry
(plan §Risk row 1).

## Sync engine integration (zero changes)

`swap_ref_sha` resets `sync_etag = None` + `remote_path = None`. The
existing `PushWorker` (Fast lane, debounce 1.5 s) and `BackgroundWorker`
(Slow lane for ≥100MB) drain the queue automatically on the next polling
tick — no migration-specific sync code needed.

## Risk surface (still open, mitigated in module design)

Per plan §Risk:
| Risk | Mitigation in 4.6.1 |
|---|---|
| Mid-migration crash | per-entry independence; journal incremental write at end |
| User cancels mid-run | resumable via `check_needed()` re-probe (already-faststart entries skip) |
| Disk space | NOT pre-checked in 4.6.1 — will add to 4.6.2 frontend prompt |
| Synology push storm | `swap_ref_sha` flips `sync_etag`; existing lane_for_size routes large blobs to Slow lane |
| Cross-device ref inconsistency | per-device migration; sync engine dedups via sha (Stage 4.5.7 verified) |
| Backup folder disk cost | documented in plan; user can manually delete sooner than 7-day GC |
